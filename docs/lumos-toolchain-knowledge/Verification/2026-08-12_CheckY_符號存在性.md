# 驗證：Check Y（被提及符號存在性）

## 最值得記的一件事

★**上線當天抓到 3 條真錯，而這 3 條在同一天 10 個 agent 的兩階段交叉審計中全被漏掉。**★

| 節點 | 架構圖寫 | 實際 |
|---|---|---|
| 活動報名 | `ActivityService.RegisterAsync` | `SubmitRegistrationAsync` |
| 滿額贈 | `ListAvailableAsync` | `GetActivitiesAsync` |
| 滿額贈 | `GetOrdersForRedeemAsync` | `GetOrderSelectionAsync` |

**為什麼 agent 會漏**：實證員驗的是「行為對不對」。方法名寫錯、但行為描述正確，就滑過去了——
其中 `ListAvailableAsync` 那條，昨天的實證員甚至在證據裡順口寫了「Server ListAvailableAsync **即** GetActivitiesAsync」，
**它看到了差異卻沒把它當成 finding**。

> ★**人和 agent 都會盯著語意而放過名字，機器剛好相反。**★ 一個 30 行的機械檢查補上了 10 個 agent 的盲區。

## 一個諷刺但有價值的發現

**2026-08-12 訂正架構圖時，我們自己寫的訂正句觸發了誤報**：

> 「`RefundPointsAsync` 全庫零命中」「原記 `RegisterAsync` 無此方法」

節點是**正確地在記錄「這東西不存在」**——對它報「repo 查無」是把正確紀錄當錯誤。
這直接證明了否定語境豁免的必要性，也是「**寫檢查的人自己第一個踩到**」的好例子。
