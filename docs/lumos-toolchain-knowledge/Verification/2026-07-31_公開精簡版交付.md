## 額外修正:slim-scan.py 的 prose 形態假陽性

**現況**:`` `./install.sh` `` 會被判成對已移除指令 `install` 的 `prose` 命中——那是檔名不是指令引用。原邊界只排反引號/字母/連字號:

```python
re.search(r"(?<![`\w\-])" + re.escape(cmd) + r"(?![\w\-])", line)
```

`/install.sh` 裡 `install` 前面是 `/`、後面是 `.sh` 的 `.`,兩者都不在排除清單裡,誤判成裸散文引用。

**先加紅測試**(`t_slim_scan_filename_fp`,放在 `t_slim_scan` 之後):

```
✗ ★假陽性修正★ `./install.sh` 不命中(第1行)  [{'form': 'prose', 'text': '1 檔名(相對路徑開頭,不得命中): 跑 `./install.sh` 安裝'}, ...]
✓ ★假陽性修正★ scripts/install-hooks.sh 不命中(第2行)
✓ ★真陽性不受影響★ 真裸散文引用仍命中(第3行)
────────────────────────────────────────
2 passed, 1 failed
```

(第2行案例其實在修正前就已經因為後接 `-hooks` 的連字號被舊 regex 擋下,不是這次修正的目標,但納入測試矩陣做完整覆蓋。)

**修正**:負向前瞻/後顧多排「前接 `/`(路徑分隔)」與「後接 `.<字母>`(副檔名)」:

```python
re.search(r"(?<![`\w\-/])" + re.escape(cmd) + r"(?![\w\-])(?!\.\w)", line)
```

**修正後全綠**:

```
✓ ★假陽性修正★ `./install.sh` 不命中(第1行)
✓ ★假陽性修正★ scripts/install-hooks.sh 不命中(第2行)
✓ ★真陽性不受影響★ 真裸散文引用仍命中(第3行)
```
