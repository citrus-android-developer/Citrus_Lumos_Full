# 驗證層去模型化_計劃

> 緣起(2026-08-08,Enzo 裁定入帳):canary 的根本困境=「有抓到不代表認真,沒抓到不代表不認真;模型能力上升 → miss 率趨零 → 計分訊號飽和;整個機制在不停變動的系統(模型換代/spec 各異/植針難度人拿捏)裡找穩定規律——跨期統計站在流沙上」。系統 8/4 已把 design-loop 的 canary 踢出閘(d4 觀測化),本案推進兩步:①canary 定位正式收縮成「當輪煙霧偵測器」②code-loop 同步降級+以模型無關判準補位。

PRIOR-ART: ① 最小解層級——處置閘(design-loop 已驗證,本週三個 loop 實戰含 rc0 收斂)移植 code-loop;變異測試=既有 `guard kill`(合約點沙盒破壞)思想泛化到 diff 層,測試選擇複用既有 `testmap affected`(檔↔測試依賴圖);翻紅釘=TDD 紅綠既有慣例升收貨規則;其餘全 skill 文本/架構圖裁定。② 世界解:mutation testing=業界成熟(mutmut/cosmic-ray/PIT;diff-based mutation 有文獻與 CI 實務)——零依賴家規排除引套件,算子自寫(python ast,三種起步);「finding 須附可執行重現」=2026-08-01 治理日報吸收(十個唱反調審查員一致背書不存在漏洞,只有強制實跑才殺掉)。③ Growth test 三問:事故=Enzo 非平穩性論證+canary 天花板實證(canary-audit 已載「真醒vs演醒不可分」+Anthropic workspace 論文)+8/1 phantom-vuln 日報;非風格(閘的判準漂移=可量測的治理風險);既有機制小修蓋不住「考人」的結構問題,但補位件全是既有機制泛化。④ 裁定=borrow-design。

## 四件(S1-S2 純文字/架構圖,S3 收貨規則,S4 唯一新碼)

### S1 canary 定位收縮(design-loop 側,零代碼)
- 架構圖裁定入帳([[Systems/canary-audit]] KEY+decision):canary=**當輪煙霧偵測器**——只做同輪席間對照(多席抓到、一席沒抓到=當輪異常,查該席管線:context 截斷/檔沒給到/工具壞/降級路由),**不做跨期統計、不做席位信譽分、不做型別抽樣權重**(D 案的權重工程半正式否決,理由=非平穩性;型別帳降為描述性紀錄)。
- 判讀規則一句話入 skill:「漏送分題=強警報(連這都沒抓到);漏難題=弱訊號(不苛責);抓到送分題≈零證明;抓到難題=真醒著」——當輪判讀,非統計。
- 型別報表結清:canary-stats 現有輸出即第一份描述性報表,入 Verification 結清「攢滿 15 筆」驗收(r1 折入:記帳附可重算來源——命令+全帳母體+截至 ts+帳本行數,漂浮數字不入 Verification);型別統計**到此為止不再蓋樓**。
- **SNR 前瞻層明文豁免(r1 折入,s3 blocker:勿誤殺已驗證資產)**:[[Projects/驗證層自證三件_計劃]] 的 canary_snr 前瞻層(固定題×同席重跑的受控矩陣)**不在本否決範圍**——它是同題重複測量的實驗設計,非流沙上的跨期觀察統計;但非平穩性同樣制約它:語料按 model epoch 分層、模型換代=重新校準,不做跨代比較。否決範圍精確=「對自然發生的 caught/missed 流水帳做跨期統計推論」。

### S4 diff 變異測試 v1(唯一新碼;「植針考測試」取代「植針考人」)
- **與 code-loop 既有步驟 7 的關係(pre-flight 抓回)**:S4=把該手動步驟自動化;**分桶語意 v1 為子集**(r1 勘誤,Codex:原「沿用」誇大)——v1 五桶=killed/survived/no-test-selected/timeout/error;步驟 7 的 NoCoverage(raise 探測雙跑法)成本×2,列 v2,縮水如實聲明。
- `lumos mutate --diff <range> [--json]` 演算法明文(r1 折入,原稿多處未定義):
  - **算子=python `ast` NodeTransformer**(非字串置換——字串/註解裡的 and/== 天然免疫,r1 抓回 guard-kill 字串置換法不適用自動生成):①Compare 運算子成對反轉(Eq↔NotEq、Lt↔LtE、Gt↔GtE;鏈式比較每個 op 單獨成一變異)②BoolOp And↔Or ③**僅 Compare 運算元中的 int 常數** ±1(各產一變異;其餘常數不碰——port/timeout/status code 類無關數字排除,r1 折入)。
  - **變異範圍=僅 diff 新增/修改行(`+` 行)所在語句**(unified diff 行號解析;context 行不變異——考的是這次改動)。
  - **baseline 前置(r1 blocker,s1)**:worktree 先跑選測集,**baseline 非全綠=abort 不計殺活**(沿 guard kill 慣例)——否則紅/flaky 測試把「殺」系統性灌水。
  - **runner 合約(r1 blocker,Codex)**:沿 guard kill 的 platform config `run_cmd` 合約({method}/{file} 代換);無 config 時本 repo fallback=`python3 <測試檔>`(stdlib harness 慣例);兩者皆缺=error 桶。
  - **測試選擇**:對原始 diff range 跑一次 `testmap affected` 取聯集;**testmap 的 stale/fail-open 各自標注**(r1 折入:map 缺失/壞損/stale 與「真無邊」是三種不同事實,混報=把基建故障誤當測試洞)——stale 時輸出加 `map_stale:true`,map 不可用=error 桶非 no-test。
  - **cap 決定性(r1 折入,兩席)**:預設 cap=100;超限取 `sha256(diff_range + file:line + 算子簽名)` 排序前 N(人人可重算,無 random;沿 panel 抽查的決定性公式慣例)。
- 輸出:殺率+活口清單(survived 桶,file:line+變異描述)+各桶計數;**rc 合約修正(r1 折入,Codex)**:rc0=觀測有效(不論殺率);**基礎設施失敗(worktree 建不起/runner 缺/baseline 全紅)=rc2 fail loud**——「恆 rc0」原句作廢,0% 殺率與 0 個變異跑成必須可區分。
- 邊界:v1 僅 .py;單變異單跑;survived 的兩種成因分開(測試網洞 vs no-test-selected 選測失接,r1 折入不混報)。
- 誠實射程:殺得死機械變異≠殺得死真缺陷;等價變異誤列活口——v1 接受,人裁剔除;worktree 清理=finally(r1 勘誤:原「atexit+finally 雙保險」不實,guard kill 現況僅 finally,沿用不加碼)。
