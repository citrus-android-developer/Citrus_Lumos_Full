# 結清式收斂（AREX 借鏡）計劃

> 緣起：2026-07-27 調研日報三篇（AREX／LoopTrap／Sage）齊指「驗證層自己可不可信」。便宜可直接落的當日已 ship（rubric、終止輸入紀律）；這裡收「要設計才能動」的部分。

PRIOR-ART: ① 最小解層級——非新機制，是既有收斂閘（loop status 四條合取 K-streak∧G1∧G2∧G3）的判準升級，opt-in 疊加。② 世界解——AREX（arXiv 2607.21461）內圈生/外圈逐條約束查＋結構化壓縮；其「驗證比生成便宜、因可拆逐條檢查」前提與本方法論同賭注。③ 裁定=borrow-design（借判準設計，原生實作進 lumos loop status，零依賴不變）。

## 規格（[S] 條款，落地 Verification 認領）

- [S1] **結清模式收斂閘（opt-in，v1 只接 legacy 路徑）**：`loop status --gate --settle <清單檔>`（`--settle` 為**本計劃新增旗標**，現行 CLI 尚無）。
  - **模式邊界（r1 折入）**：現行三種收斂判準並存（legacy K-streak／`--panel` 結構信號／`--light` 單席謂詞，互斥）。v1 的 `--settle` **只替換 legacy 的 K-streak 條件**；與 `--panel`/`--light` 併用＝**rc2 互斥**；`--settle` 無 `--spec`＝rc2（沿 --light 先例）；無 `--gate`＝rc2（新規，fail-closed）；顯式 `--need` 或 `--min-seats` 與 `--settle` 併用＝rc2（r5 理由修真：legacy gate **現行有**消費 min-seats（逐輪驗 auditor 非空，scripts/lumos:3038-3046）——rc2 真理由＝該檢查定義在 need 窗上、settle 拔窗後無定義域；其「auditor 非空」職能由 settle 承接＝**「caught 輪」定義收緊:kind=caught 且 auditor 非空才算;否則(kind≠caught ∨ auditor 空/缺)一律視同 missed**——本 spec 各段(貶值規則/G3 末筆)所稱「missed 輪」均用此擴義（r5 折入,堵空席背書））。清單檔不可讀、格式非法或**零條目**＝rc2（測試策略既有句的規格鏡像,r5 同步——零條目全結清恆真=零證明,拒收）。settle gate 讀帳遇不可解析行＝rc2 fail-closed（不沿 legacy 靜默跳行——跳行使 append 序位移、`verified_in_round` 錯位）；**半徑明文（r5）**：壞行無法歸屬 loop（loop 欄在解析後才可讀），此 fail-closed 及於整個共用 log 檔——別的 loop 弄髒一行、settle gate 全擋,刻意接受（fail-closed>可用性）。panel/light 的 settle 化留後續評估，不在 v1。**settle v1＝手動 loop 專用（r5 修正：已知限制而非偵測機制）**：`loop next` **不認得 settle loop**（log 無標記、CLI 收不到清單檔——機械偵測依據在 v1 不存在），對 settle loop 使用會照完整 legacy gate（K-streak∧G1∧G2∧G3）判——off-fold 改版場景 legacy G3 鏈多半先斷、**更常見是誤報「未收斂」白燒輪**,純 fold 場景則**可能誤報收斂**（兩向都真,r5 補）——v1 紀律＝settle loop 勿用 `loop next`、直接問 gate（記入誠實邊界）；自主 loop 接線（含機械偵測：候選＝清單檔固定落點 `.lumos/settle/<loop-id>` 或 record mode 欄）＝後續版前置條件。G1／G3 照舊合取；**G2 在 settle 下降 advisory**（r2 裁定：枯竭是「數趨勢」概念，結清模式的存在證明本就取代它——不再懸置）。**G3 settle 版（r2 折入 need-窗、r4 裁定重錨=選項②）**：settle 不數輪、也**不驗逐輪鏈續性**（off-fold spec 改版是 settle 主場景，逐輪鏈在生命期窗下必死鎖——r3 blocker 裁定）；settle 版 G3＝「**末筆 record 的 result hash＝當前 spec**」（r5 收斂定義:條目 spec_sha 檢查歸「清單全結清」條件單軌承擔,G3 不重複合取——定義層與歸因層對齊）。版本完整性由條目級 sha 逐條錨住（誰在哪一版被查證，比輪間鏈更細粒度），鏈續性的職能被其取代——誠實代價：輪與輪之間的「篡改序列」不再被驗，防線收斂為「終態全對齊現檔」（進誠實邊界）。**邊界態 fail-closed（r5 折入）**：「settle 帳」＝canary-log 中 loop==id 的記錄序列（與清單檔是兩本帳）；半帶/unbound 檢查窗＝settle 帳全生命期（不吃 need 窗）；末筆 record 無 result hash 欄＝G3 ✗；settle 帳零 record＝✗；hash 半帶＝✗；末筆為 missed 輪＝G3 照驗 hash（版本證據不依賴審計員醒著——該輪 llm-ok 已由貶值規則處理，兩閘分工明文接受）；實作＝settle 專用謂詞，不復用 _hash_chain_check 的鏈續性段。**失敗歸因單一化**：條目 sha 不符→報「清單未結清（哪條過期）」；G3 只報「末筆 result≠現檔」——不雙報。
  - **約束清單**：spec 的硬合約／載重宣稱逐條列成機械格式，一條一狀態：`unverified`（未查）／`mech-ok`（機械查訖：refcheck 通道，僅買「引用存在／行號有效」）／`llm-ok`（語意查訖：LLM 實質查證過宣稱成立）。狀態名刻意不用 audited（避免與合約鏈 `[audit:]` 撞語意——那是「合法性」審計，這裡是「宣稱成立」查證，兩軸不同）。
  - **結清終態規則（r1 折入，堵語意條機械放行）**：機械條（純引用存在性宣稱）`mech-ok` 即結清；**語意條必須 `llm-ok` 才結清**——`mech-ok` 對語意條只是中繼態。條目建檔時標 `kind: mech|semantic`（人拆時判）。
  - **canary 醒著條件保留（r1 折入，r2 補記帳鏈）**：settle 輪照 skill 紀律植 canary；條目欄位含 `verified_in_round`（哪一輪推進到 `llm-ok`）；**回滾＝gate 讀時貶值，不回寫檔**——gate 讀清單＋canary-log，凡 `verified_in_round` 為 missed 輪的 `llm-ok` 條目**視同未結清**（append-only 帳不動、清單檔不動、gate 保持唯讀）。**輪鍵（r4 裁定）＝該 loop 在 canary-log 的 append 序號**（第 N 筆 record＝第 N 輪；append-only 帳下唯一且機械可導,不加新欄、不撞 panel round 欄混用守衛）；`verified_in_round` 指向不存在的序號＝**fail-closed 視同未結清**；llm-ok 條目**缺**此欄＝清單格式非法 rc2（schema 強制,r5 折入）。「查證的人醒著」仍是語意條結清的前置。**狀態機補全（r2）**：純語意宣稱（無引用可 refcheck）可 `unverified` 直跳 `llm-ok`；`mech-ok` 僅對含引用宣稱的條目有意義。
  - **清單↔spec 版本綁定（r1 折入，r2 粒度歸一）**：**條目級** `spec_sha`——每條記拆分當下的 spec sha；gate 時任一條目 sha ≠ 現行 spec sha＝該條過期、清單未結清 rc1，**由人（或編排者留痕）逐條重拆或「確認未受影響」＝重蓋該條 spec_sha＋note 理由**（不自動重開——機械歸因「哪條受影響」是後續題）。條目失效軸＝**spec 內容變更（hash）**，不是輪次計時。
  - 收斂＝清單全結清 ∧ G1 ∧ G3（G2 advisory 印出不進合取，r2 已裁）。高風險 spec（金流／對外寄送／prod 不可逆／守衛面，對齊 skill 四類）建議用；一般 spec 維持 K-streak。與既有「高風險建議 `--need 3`」的關係：settle 取代 need（結清是逐條存在證明，不再數輪）——落地時同步範圍＝SKILL.md＋CLAUDE.md skill 表＋SKILL 內 gate 指令模板（三處都硬編 need，防散落漂移）。
- [S2] **結構化壓縮（治長跑 governance decay 殘餘面）**：自跑迴圈長上下文不交通用摘要，壓成「已驗證證據＋未結約束」兩欄結構化狀態；硬合約、「停在放行點」、anchor 驗證列入**壓不掉白名單**。
  - **價值域校準（r1 折入）**：架構圖既有裁定（[[Systems/autonomous-iteration-loop]] 2026-07-26 對帳）＝架構已有結構性 counter（每輪重注入／fresh spawn），殘餘面只剩「對話中途口頭約定」——本條治的是**殘餘面**，非全開的洞。
  - **掛載面（r1 折入）**：自主 loop 的編排入口與 scratch 狀態（`governance/autonomous_loop/orchestrator-prompt.md`、`governance/autonomous-loop.sh`）；輸出 schema／檔名／消費步驟＝待辦展開。
- [S3] **獨立進度驗證器（LoopTrap 貴的那半）**：收斂／進度判斷由一個**看不到被審材料**的小驗證器覆核——只讀帳面結構欄位（findings 計數、settle 清單狀態、canary caught/missed），不讀 spec/報告散文。
  - **誠實界定（r1 折入，辯方裁後措辭校準）**：這些帳是「結構欄位」不是「客觀真值」——findings 數與 severity 源頭仍是 LLM 裁決、canary 帳由植入者自判（既有系統天花板，非本計劃新增）；驗證器隔離的是**散文注入面**，隔離不了「帳本由被驗方書寫」。**已知合法散文通道＝record 的 `--note` 欄與 `--clusters` 理由字串**：驗證器輸入契約必須做欄位級過濾（只讀結構欄位、丟棄 note/clusters 理由）；**輸入源＝直讀 `.canary-log.jsonl`＋清單檔，不吃 CLI stdout**（loop status 輸出行印 note，吃 stdout 濾不掉）——[S3] 測試的對抗散文即從 note 欄注入（通道明確，測試不空轉）。

## 邊界（明確不做）

- 不替換現行 K-streak 閘（settle 為 opt-in；不帶 `--settle` 行為 bit 不變）。
- v1 不接 `--panel`/`--light`（互斥 rc2；panel 的結清化留後續）。
- 不自動生成約束清單 v1（人拆；**編排者代拆時清單完整性回到 maker bias**——見誠實邊界）。
- 壓縮工具不外掛模型（規則式白名單結構）。

## 首個真實 loop 回饋（dogfood，2026-07-31）

> 對象＝[[Projects/公開精簡版_計劃]]（離職交接用的 CLI 子集）。該 spec 先跑了兩輪 panel（各 5 席＋跨家族席）皆未收斂，`capture-recapture` 殘餘反而從 7.00 升到 22.50（每輪折入的新散文自帶新缺陷），故轉走結清模式。**這是 v1 的第一個真實 loop**，本節記三條實測回饋。

### ① ★settle 的任務框架會壓低 canary 命中率★（新的已知限制）

同一份 spec、同一批模型（sonnet）、同一位編排者植餌：

| 模式 | 派工 framing | canary 命中 |
|---|---|---|
| panel r1 / r2 | 「主動找洞，你一定找得到至少一個未定義的詞／壞引用／不一致」 | 4/5、4/5 |
| **settle** | 「逐條查證清單」＋附帶一句「發現條目以外的問題一併列出」 | **1/3** |

**判讀**：條目清單把注意力吸走了——查證員把力氣花在「逐條給裁決＋附證據」，「條目以外的挑洞」退成次要任務。這不是審計員退步，是 framing 沒為結清模式重新校準。

**建議修法（未實作）**：settle 輪的派工模板須**額外加重**條目以外的挑洞義務（不能只在結尾附一句），或改成「先挑洞、再逐條裁決」的兩段式；canary 難度校準**不可沿用 panel 輪的直覺**。→ 進 [S1] 待辦。

### ② ★canary 在 settle 下的價值高於 panel★（正面實證）

漏餌的 V1 席交出**「12 條全裁成立 ＋ 無額外問題」**，證據紮實、行號逐一精確——卻漏掉植在**它主查條目那一句括號裡**的未定義常數。若無 canary，這 12 條會被記成結清，且外觀上比「跑三輪不收斂」體面得多。

**這正是本節點〈實務隱患〉self-governance 條所警告的失效樣態被真的接住一次**：存在證明（「我查過了」）比缺席證明（「沒人挑到」）更容易被說有就有，**因此 settle 下的醒著條件不是可選的保險，是主承重**。r1 折入時保留 canary 醒著條件的裁定，在此得到實證支持。

### ③ ★settle v1 無法承接已有 panel 歷史的 loop★（機械限制，不在既有已知限制清單）

`--settle` 對已有 panel 記錄（帶 `round` 欄）的 loop **在 settle 邏輯之前就 rc2**——混用守衛先擋（「canary-log 含 round 欄卻未加 --panel」）。實務後果：**panel 跑到一半想轉 settle，只能開新 loop id 承接**（本案用 `<原 id>-settle`，沿 light→standard ratchet 的後綴慣例）。

**代價**：舊 loop 的 canary 證據**不進新 gate**——settle gate 只認新 loop 自己的記錄。本案 r1／r2 共 10 筆記錄因此不替結清背書。

這條與〈邊界〉「v1 不接 `--panel`」是同一裁定的**下游後果**，但原文只說「併用 rc2」，沒說「**有 panel 歷史的 loop 也用不了**」——兩者不同（前者是旗標互斥，後者是帳本狀態互斥）。→ 建議補進 [S1] 模式邊界，或在 panel→settle 轉換上做 migration 路徑評估。

### ④ ★重蓋疲勞張力的完整實例（2026-08-01 補，該 loop 已終結）★

本節點〈誠實邊界〉早已預警「條目級 `spec_sha` × 每輪 fold 必改 spec → 每個有 findings 的輪後全清單過期……活躍 loop 裡恐橡皮圖章化」。**公開精簡版這個 loop 走完全程，是該限制的完整實例**：

- settle 三輪後進入實作，實作階段十餘次 fold，**每次都讓整份 35 條清單過期**
- 更關鍵：`[S3]` 條款在 settle 輪之後**又被實質改了三次**（絕不碰 CLAUDE.md → 只准附加 → 可移除既有區塊並策展）。**當初查證那 11 條的查證員，看的是一份現在已不存在的規格**——重蓋 sha 等於拿舊考卷答案交新考題
- 最終處置＝**使用者裁定停在 21/35 未結清、GATE FAIL 為終態**，如實留痕而非塗綠

**新增的觀察（前三條沒涵蓋的）**：
- ★**「實作完成、測試全綠」不能用來結清語意條**★——編排者實測踩過：把 18 條語意條標 `mech-ok` 想推進，未結清數從 10 **漲到 18**（`mech-ok` 對語意條是中繼態）。**終態規則擋對了**，但這也顯示「下游實作證據無法回流結清上游語意條」是結構性的，不是操作失誤。
- **推論**：settle 對**改版頻繁的 spec** 不適用。它的假設是「spec 拆完清單後相對穩定」；一旦進入實作、spec 隨實作發現持續演進，條目級 sha 綁定會讓清單永遠追不上。**適用邊界建議寫進 [S1]：settle 適合「已凍結或近乎凍結的 spec」，不適合「邊做邊改的 spec」。**

### 附帶觀察（非缺陷）

- **失敗訊息的可讀性明顯優於 panel**：panel gate 只說「輪無效／存活≥major／殘餘超門檻」；settle gate 直接列出**哪 21 條未結清、各自為什麼**（貶值／未查證）。
- **進度會累積**：14/35 已結清且只要 spec sha 不動就不必重做；K-streak 模式下每輪重來。這是結清模式對長 spec 的真實優勢。
- **重蓋疲勞張力（既有已知限制）實測命中**：本輪折入後 spec sha 一變，35 條全部過期須逐條重蓋——本案由編排者留痕重蓋（非人逐條確認），**正是該條警告的橡皮圖章化**，如實記錄。

## 誠實邊界

- **首個真實 loop 的清單由編排者代拆、使用者未逐條刪改即採用**（2026-07-31）——正是下一條警告的情境真實發生，該輪**不宣稱清單完整**。
- 結清＝「列出來的都驗了」，**清單本身漏列的照樣漏**（清單完整性是新的單點）；v1 靠人拆＝人的注意力上限，**編排者（LLM）代拆時清單完整性直接回到 maker bias**——被閘的一方拆自己的驗收清單，此半無外部守衛（r1 折入）。
- AREX 的前提「驗證可拆成便宜逐條檢查」對語意合約只部分成立——語意條的單條查證仍是 LLM 判斷，rubric 化能錨定但不消除判官不穩（Sage 天花板同在）；canary 醒著條件買的是注意力下限，不是查證正確性。
- **G3 選項②的代價（r4 折入）**：settle 下不再驗輪間鏈續性——「中途某輪審的是被篡改副本」這類序列證據不被機械驗，防線收斂為「終態全對齊現檔」＋條目級 sha；接受理由＝條目 sha 粒度更細且 off-fold 改版是常態，逐輪鏈在此語境必死鎖（r3 blocker）。
- **loop next 盲區（r5 折入，v1 已知限制）**：`loop next` 機械上認不得 settle loop，誤用會照完整 legacy gate 判：常見向=誤報未收斂白燒輪、危險向=誤報收斂——v1 靠紀律（勿對 settle loop 用 loop next），自主 loop 接線前必須先解機械偵測。
- **append 序錯位風險（r5 折入）**：輪鍵＝append 序的前提是帳完整可解析且無補記——settle gate 對壞行 fail-closed（rc2）擋解析缺口；「事後補記/刪行/截斷使序號位移或錯亂」無機械守衛，靠 append-only 紀律。
- **重蓋疲勞張力（r3 折入）**：條目級 spec_sha × 每輪 fold 必改 spec → 每個有 findings 的輪後全清單過期、須人逐條確認重蓋——活躍 loop 裡恐橡皮圖章化，守衛訊號被稀釋；緩解候選（重蓋粒度=段落 hash/只重蓋受 fold 觸及段的條目）進 [S1] 介面設計裁。
