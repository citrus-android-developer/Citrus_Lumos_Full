# 檔案↔測試依賴地圖_計劃（①）

## 目標與問題

TDD／code-loop 迴圈裡「改了 X，該跑哪些測試」目前靠人腦或全跑。`test-layers` 只到**棧層**粒度（碰 .cs → 跑 C# 層）；本案補**檔案**粒度：src 檔 ↔ 測試檔的邊，advisory 推薦，並反向暴露「沒有任何已知測試指向它」的裸檔。

`PRIOR-ART:` TIA（test-impact analysis）生態——pytest-testmon（動態 coverage 圖，單語言）、Jest `--findRelatedTests`（靜態 import 圖）、Bazel `rdeps`（建構圖）。本 repo 群多語言（kt/cs/vue/sql/py）且零依賴家規，動態 coverage 與 AST import 圖皆不可得 → 裁定 **borrow-design**：借「diff→受影響測試」的產品形態，原生實作為三路訊號靜態近似（naming 慣例＋content 引用＋git 共變），精度天花板如實聲明、advisory 不硬擋。

## 範圍刀（明確不做）

- **不做**動態 coverage、不 parse AST、不解析 import 語句（多語言 parser＝依賴地獄）。
- **不做**硬閘：`affected` 恆 rc0（同 `test-layers` advisory 家族）；不掛 pre-push、不進 doctor。
- **不做**測試「方法」粒度；粒度到**檔案**為止。
- **不自動 rebuild**：map 是顯式 `build` 產物；陳舊性只提示不擋（見 [S2]）。
- v1 **不掛 hook**；skill 文件僅一行提及（見 [S5]），深整合待實戰回饋。
- v1 常數（conf 值、stem 門檻、掃描上限、cochange support 門檻）**刻意寫死不開設定檔**——先讓 [S4] 驗證裁值，有實戰回饋再考慮 `.lumos/` 覆寫（明文取捨，非疏漏）。

## 條款

### [S1] `lumos testmap build [--repo R] [--json]`——三路訊號挖掘

vault-free。定根：`--repo R` 或 `_anchor_repo_root` 自動解析；build 前置驗證 **R 必須是 repo 根**（`git -C R rev-parse --show-toplevel` 輸出 strip 後與 R **雙方皆 `Path.resolve()` 再比對相等**——macOS `/tmp`→`/private/tmp` symlink 落差靠 resolve 吸收；不等＝子目錄或非 repo → stderr 診斷＋rc2。子目錄會讓 ls-files（子樹相對）與 git log（root 相對）路徑空間不相交、靜默零邊，故必驗）。**本指令自發的 git 呼叫**（rev-parse/ls-files）一律 cwd=repo_root＋`timeout=30`；**沿用的 cochange 挖掘鏈維持現碼（無 timeout）**——不改共用函式以免波及 cochange 家族，大 repo 全歷史挖掘可能久跑，明文天花板。輸出 `<root>/.lumos/testmap.json`：

```json
{"version": 1, "built_at_commit": "<HEAD sha>", "built_at": "<UTC ISO-8601 秒級>",
 "edges": [{"src": "a/B.cs", "test": "t/BTests.cs", "sources": ["cochange","naming"], "conf": 0.9}]}
```

- `edges` 依 (src, test) 字典序、每邊 `sources` 字典序（範例即字典序）——**確定性承諾限 `edges`**（`built_at*` 明文排除）。map 內 `sources` 值域＝`{"naming","content","cochange"}`；affected 輸出側值域＝此集合 ∪ `{"self"}`。
- 寫檔：先 `mkdir(parents=True, exist_ok=True)`；tmp 同目錄（`.lumos-tmp` 後綴＋try/finally 清殘檔，同 scripts/lumos 既有寫檔慣例）、`os.replace` 原子覆寫；**mkdir/寫入/replace 的 OSError → stderr 診斷＋rc2**，stdout 摘要行僅在寫檔成功後印。產物不進版控（實作時本 repo `.gitignore` 加 `.lumos/testmap.json` 一行；目標 repo 未加＝髒 worktree，可接受，不代人改檔）。
- **unborn branch（零 commit，偵測點＝`rev-parse HEAD` 失敗）** rc2＋明訊息；含換行檔名不支援（未用 `-z`，明文限制）。

**檔案全集**＝`git -c core.quotePath=false ls-files`（cwd=root；追蹤檔）。路徑一律 repo-root-relative。

**副檔名白名單（字面值集合）**＝`{kt,java,cs,py,ts,tsx,js,jsx,vue,swift,sql}`（副檔名比對大小寫不敏感）。測試檔與候選 src 檔都先過白名單。

**測試檔判定**（白名單內，下列三者取聯集；各自比對規則如各句明定，不共用大小寫規則）：
1. **路徑段**：命中 `(^|/)(tests?|__tests__|specs?)/`（大小寫不敏感；尾隨 `/` 必須——`$` 分支已刪，白名單前置下無副檔名檔不入場，死分支）。
2. **`Path.stem` 前綴/尾綴**（stem＝`Path` 語意，只剝最後一段副檔名）：前綴 `test_`（小寫字面，大小寫敏感）；或尾綴命中綴詞表——**底線變體** `_tests`/`_test`/`_specs`/`_spec`（大小寫不敏感，底線即邊界）；**駝峰變體**：複數 `Tests` 全副檔名適用；單數 `Test` **僅限 `.java`**（JUnit 主場——他語言 `LoadTest.cs`/`SmokeTest.kt` 類領域名詞誤殺率高，明文取捨）。皆**大小寫敏感**字面（ASCII `A-Z` 定義大寫）、前字元須非大寫（小寫/數字/`.`/`_`；**stem 恰等於綴詞（`Tests.cs`）＝無前字元＝判測試檔、剝後空 stem 不建邊**）——`FooTests` ✓、`Foo.generated.Tests` ✓；`Contest`/`CONTEST`/`ProTEST` 字面不符 ✗；`ABTest`/`APITests` 前字元大寫 ✗（縮寫類漏判記取捨）；**駝峰 `Spec(s)` 刻意不收**：`PodSpec`/`OpenApiSpec` 類領域名詞是 k8s/OpenAPI 標配，誤殺真 src 的代價大於漏掉罕見的 `FooSpec` 測試慣例——後者靠路徑段/內容/cochange 兜，明文取捨）。
3. **多段檔名標記**：完整檔名含 `.spec.` 或 `.test.` 段（小寫字面，大小寫敏感；`Foo.spec.ts` ✓）。

**候選 src 檔**＝白名單內、且非測試檔。（無副檔名檔如 `scripts/lumos` 不入候選——天花板，見 [S4]。）

**訊號一 naming**：src-stem＝src 檔 `Path.stem`。測試檔比對 stem：完整檔名只剝最後一段語言副檔名，緊鄰其前是 `.spec`/`.test` 標記段則連同剝除（`Foo.spec.ts`→`Foo`；不泛剝點段，`Foo.generated.Tests.cs`→`Foo.generated.Tests`）；再依綴詞表**單次**剝尾綴（實作按表 `_tests`,`_specs`,`Tests`,`_test`,`_spec`,`Test` 順序逐一試、先命中先剝；**剝離比對規則與判定同套**：底線變體大小寫不敏感、駝峰變體大小寫敏感＋前字元非大寫邊界——`tests/ABTest.cs` 判定靠路徑段、剝離時 `Test` 不過邊界故不剝；無尾綴才剝前綴 `test_`），**剝後尾端殘留 `.` 或 `_` 一併去除**（`Foo.generated.Tests`→剝 `Tests`→去尾點→`Foo.generated` ✓；`foo_spec` 直接命中 `_spec` → `foo` ✓）。剝後與 src-stem 大小寫不敏感全等 → 邊，conf=0.9。多個同 stem src 檔＝各建邊。**建邊判準＝剝離管線（標記段／綴詞表／`test_` 前綴任一路）有實際發生剝離**（`Foo.spec.ts`→`Foo`、`test_foo.py`→`foo`、`Foo_TESTS.py`→`Foo`（`_TESTS` 大小寫不敏感命中 `_tests`）皆算）；**無任何剝離者原則不建 stem 邊**（`tests/helpers.py`），**唯一例外**：同 stem src 恰 1 個且 stem 非 dunder（`__xxx__`）→ 建邊——恢復 `__tests__/Button.tsx`↔`Button.tsx` 同名慣例、擋 `tests/__init__.py` 對全庫爆炸（同 stem >1 或 dunder＝不建）。

**訊號二 content（內容引用）**：測試檔內文（UTF-8 `errors="ignore"`）詞邊界 regex 匹配 `re.escape(src-stem)` 或 `I`+src-stem（C# 介面 DI 慣例）；大小寫敏感；len(src-stem)<4 不建邊（`I`+stem 亦不搜）。`IMember.cs` 與 `Member.cs` 並存且測試文含 `IMember` → 兩 src 各建邊（誠實多指）。全部 src-stem（含 `I`+stem 變體）合併單一 alternation regex、`finditer` 收集**全部相異命中 token** 再經 token→srcs 多對多表反查（`re.search` 首命中撐不起多指宣稱）；單檔 200KB 上限（磁碟位元組，讀前 stat 判）；超限或讀檔 OSError → 逐檔跳過 content、stderr 記一筆。→ 邊，conf=0.5。

**訊號三 cochange**：
- `cfg, notes = _cochange_load_config(repo_root)`（二元組解包）；notes 原樣印（現碼自帶 `cochange:` 前綴；文字模式 stdout、`--json` 模式 stderr——偏離實碼「notes 走 stdout 防 hook 吞」註記係因 testmap 非 hook 場景、json 純度優先，**刻意偏離記理由防好心改回**）。
- `rules, n_txn, n_files, err = _cochange_mine(repo_root, cfg)`（四元組；`rules` 值為 `(conf, support)` 二元組，逐一解包）。
- **`rules is None`**（挖掘失敗，家族判法）→ cochange 源整條跳過＋stderr 診斷，naming/content 照出（不升 rc）。
- 只收 (src→test) 方向、src ∈ 候選 src、test ∈ 測試檔的 pair；**噪音門檻＝`support ≥ 3`**（r4 翻案：原 0.3 conf 地板方向反了——巧合邊 freq=2/support=2 的 conf 恰為 1.0 穩過地板，被擋的反而是常改真關聯;分辨巧合的量是 support,故改 support≥3=家族 min_support 預設,conf 地板刪除;[S4] 實測裁 support 門檻）；**寫入 conf＝min(挖掘 conf, 0.8) 封頂**（排序位階恆低於 naming 0.9 與自證 1.0）。
- cfg 沿用範圍：`exclude`/`max_changeset` 生效（>20 檔大重構 commit 丟棄＝cochange 源天花板，見實務隱患）；`min_confidence` 不套；`min_support` **不讀 cfg、testmap 寫死 3**（cfg 可覆寫家族值，testmap 刻意固定保確定性——調 cfg 對 testmap 無效，如實記）。

**邊合併**：同 (src,test) 多訊號命中 → `sources` 併列（字典序）、`conf = max`。

**失敗路徑（rc 矩陣窮盡）**：rc2＝root 解析失敗（`_anchor_repo_root` 回 None）／repo 根驗證失敗／非 git repo／unborn／repo 級 git 失敗（含 timeout）／寫檔 OSError；rc0＝成功。**build 總兜底**：未枚舉例外 try/except 收攏、stderr 診斷＋rc2（顯式動作兜到 rc2 非 rc0）。檔案級讀失敗與 cochange 源失敗＝降級不升 rc。**rc2 時 `--json` 的 stdout 印單行 `{"error":"<一句診斷>"}`**（純度合約全路徑守住）。

**stderr 統計（[S4] 裁值的生產端）**：`testmap: cochange support<3 擋 <N> 邊 (分佈 support=2:<n>)` 一行（不另存檔）。
**stdout（文字模式）**：`testmap: edges=<N> src=<N> tests=<N> → .lumos/testmap.json`（`src`/`tests`＝白名單候選 src 全集數／測試檔全集數——診斷語意，非「有邊的」數）。
**`build --json`**：`{"edge_count":.., "src_files":.., "test_files":.., "built_at":.., "built_at_commit":.., "path":".lumos/testmap.json"}`（`edge_count` 刻意不與 map 檔 `edges` 陣列同名——同 key 異型易錯）（欄位語意同上；path 相對 `<root>`；stdout 恆單行純 JSON，notes 走 stderr）。

### [S2] `lumos testmap affected --diff <range> [--repo R] [--json]`——advisory 查詢

定根：`_anchor_repo_root` 後做**軟版根檢查**（`git -C R rev-parse --show-toplevel` strip 後與 R 雙方 resolve 比對；不等或失敗 → 走 fail-open ②、**非 rc2**——堵「子目錄恰好也有 `.lumos/testmap.json` 時讀錯 map、git diff 在子目錄照樣成功輸出 root 相對路徑」的靜默錯配）。無 map 提示文案含「確認 --repo 指向 repo 根」。map 從 `<root>/.lumos/testmap.json` 讀。**git 呼叫 cwd=root＋timeout=30**。

**map 有效性（三級守衛）**：
1. **整檔失效**（視同無 map）：讀檔 OSError（權限/是目錄）／JSON 解析失敗／根非 object／`edges` 非 list／`version`≠1／`built_at_commit` 或 `built_at` 缺、非字串、或 `built_at_commit` 不符 `^[0-9a-f]{7,40}$`（消毒後才進 git 指令）。
2. **逐邊跳過**：edge 非 dict／缺 `src`/`test`／值非字串／`conf` 非 [0,1] 區間內有限數值或為 bool（越界如 999 → 跳該邊，防損壞 map 造最高優先假建議）。`sources` 缺、非 list → 該邊以 `[]` 代；list 內非值域元素過濾掉（不跳邊、不 crash）。
3. 有效 map 才走陳舊判定與建議。

**查詢**（diff 檔集＝`git -c core.quotePath=false diff --no-renames --name-only <range>`——`--no-renames` 使改名輸出舊+新兩路徑：舊路徑查邊、新路徑按現況歸類，堵 rename 吃掉刪檔語意）：
- 改動檔在 map 有邊（src 端）→ 取其測試檔；**建議統一過存在性過濾：測試檔須在當前 ls-files（帶 `-c core.quotePath=false`——CJK 家族坑）且磁碟為檔案（`(Path(root)/p).is_file()`，綁 root 非 cwd；`rm` 後 mkdir 同名目錄也擋）**——`rm` 未 commit 時 ls-files 仍列著，單看索引會推薦磁碟上沒有的檔（一條規則管兩路；未追蹤新測試檔不被自證＝v1 明文取捨）。src 端現存與否不影響查邊。
- 改動檔本身是測試檔（[S1] 規則現算）且現存 → 自證，conf=1.0、srcs=[]、sources=["self"]。
- 同一測試檔多路徑指到 → 輸出端去重一筆：conf 取 max、`srcs` 取聯集（字典序）、**`sources` 取聯集（字典序，含 "self"）**。`srcs` 定義＝本次 diff 中經由邊連到該測試檔的 src 清單。
- 改動的現存候選 src 檔，若其**存在性過濾後**無任何有效邊 → 「無已知測試」段（按路徑排序；邊全指向已刪測試檔的 src 也落此段——不被幽靈邊遮蔽）。非白名單副檔名與已刪除檔靜默略過（**僅限 uncovered 段收錄**，不影響「src 端現存與否不影響查邊」）。
- 建議排序：conf 降序、同 conf 按測試檔路徑。

**文字模式輸出**：有 map 首行 `map built at <built_at> (<built_at_commit 前8碼；不足 8 全印>)`；建議行 `  <conf 兩位小數> <test路徑> [<sources 逗號串>]`（sources 給人看——實務隱患的承諾落在此）；無建議印 `（無建議）`；uncovered 非空才印 `無已知測試:` 段。

**rc 合約**：恆 rc0；唯一 rc2＝缺 `--diff`（argparse 格式錯（`--diff -abc`）被 argparse 擋＝rc2 豁免於本合約；[S3] 測試用 `--diff=-abc` 等號式才踩自家守衛）。**① 的 `-` 開頭檢查在載入 map 之前**——此路文字模式不印 banner，json 全 null 形狀與文字模式一致。**fail-open（皆 stderr 診斷＋rc0）明列**：① `--diff` 值 `-` 開頭；② root 解析失敗；③ 無 map；④ map 整檔失效；⑤ git diff 失敗（range 不存在/逾時/例外）；⑥ ls-files 失敗（**建議存在性過濾**/自證/uncovered/陳舊②③ 皆依賴——⑥ 時建議一律空，不得跳過過濾輸出幽靈邊）。**總兜底條款**：全流程 try/except，任何未枚舉例外 → stderr 診斷＋rc0＋空結果——「恆 rc0」是唯一硬合約，枚舉是文件、兜底是機制。

**陳舊提示（三訊號，advisory，僅有效 map）**：獨立判定、任一真 → stderr「map 可能過期，建議 rebuild」。① `merge-base --is-ancestor` **rc1**（非祖先）→ 真；**其他錯誤**（sha 不存在/128/逾時）→ 略過①；② `git diff --name-only <built_at_commit>..HEAD` 與「（當前候選 src ∪ 測試檔）∪ map 內 edges 路徑」交集非空；③ `git -c core.quotePath=false status --porcelain --untracked-files=all` 判定：追蹤行命中同一並集；**`??` 未追蹤行改依 [S1] 判定規則現算**（未追蹤檔天然不在 ls-files/map 並集，交集法恆空＝死訊號）——是測試檔或候選 src 即觸發（不加 `-uall` 時目錄摺疊成 `?? tests/` 漏檔）——**解析規則明文**：每行取第 4 字元起為路徑、`R`/`C` 行以 ` -> ` 拆開兩側各算（檔名含 ` -> ` 的邊角不支援＝明文限制，porcelain 非 -z 無法無歧義）。訊號②同帶 `-c core.quotePath=false`（CJK 轉義=本 repo 三度踩過的家族坑）。①運算元明寫：`git merge-base --is-ancestor <built_at_commit> HEAD`。各訊號自身 git 失敗＝略過該訊號。
