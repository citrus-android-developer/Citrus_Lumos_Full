# 跨session傳訊用途調研

## 這是什麼

Claude Code 現在可以列出並直接對**其他 claude session** 傳訊——同一台機器上你另外開的視窗、雲端跑的 session 都算。對方會自己醒來處理，不需要有人在那頭操作。

這跟 [[Projects/子代理續談調研]] 講的**不是同一件事**。那邊是「續問一個已經結束的子代理」，靠磁碟上的逐字稿還原脈絡，互動視窗不寫逐字稿所以必敗。這邊是「對一個還活著的行程投遞訊息」，不吃逐字稿。先前把兩者混為一談的說法要收回，實測見 [[Verification/2026-08-14_跨session傳訊互動視窗實測]]。

## 採用候選

### ① 跨專案協同通知（Enzo 提，目前最實在）

本專案改了某個東西，另一個專案要跟著配合。現在的做法是自己切過去、把脈絡重建一遍再動手。有了傳訊就可以改完直接交代給對造的視窗。

**但形狀要對**（下方鐵則）：交代的是**指標**不是**內容**。內容的家在架構圖，跨專案共用的規則甚至該走核心架構圖升格那條路。傳訊只補「通知」這一格——那格本來確實是空的，架構圖沒有「推」的能力，只有等人來讀。

### ② 無人 loop 收斂後主動敲人

每天早上的自主迭代線跑完會停在「收斂了、等人放行」。現在得靠人想起來去看。讓它敲一下當下開著的視窗，省掉「等人想起來」這段。治理長期缺的是**觸達人**，不是算力。

### ③ 跨機器治理回報

②的延伸，治理跑在別台機器時把結果送回來。尚未驗過跨機器場景。

## 已排除

- **當審計的獨立席次**——peer 是「別人正在做別的事」，脈絡比全新子代理更髒，成本也更高。純負面。
- **當「問規則的捷徑」**——例如某專案視窗想知道某條規則升格了沒，直接傳訊來問。這跟「架構圖即唯一真相來源」正面衝突，等於多開一個繞過架構圖的破口。該擋。

## ★形狀鐵則（2026-08-14 拍板，單源在 `lumos-project-notes` skill）★

> 訊息只傳**指標與觸發**，不傳**內容本身**。

理由：訊息內容只活在對造那個視窗的記憶裡，視窗關掉就沒了。若把協同結論當訊息送過去就算數，等於在架構圖之外又長出一個沒人維護的真相源。

實務形狀：
1. 先把改動寫進架構圖（跨專案的規則走核心架構圖）。
2. 傳訊只說：我動了哪一條、去讀哪個節點、你那邊要跟的是什麼。
3. 明確要求對造把跟進結果也寫回它自己的架構圖。

## 風險（獨立於用途，採不採都成立）

實測時 peer 的回覆標頭帶 `from-mode="bypass"`——那個 session 跑在跳過權限確認的模式。合起來的意思是：**同一台機器上存在一條路，可以讓本 session 被閘擋下的動作，改請 peer 去執行。**

工具說明本身明文禁止這種用法（稱為權限洗白），但那是**自律層**，不是機制層擋得住的東西。我們整套治理建立在「閘擋得住」之上，這裡出現一條繞道。

反向的面（本 session 面對外來訊息有沒有同等戒心）本輪沒驗。子代理續談那輪有觀察到子代理對跨代理訊息會起戒心，但那不能直接外推到主對話。
