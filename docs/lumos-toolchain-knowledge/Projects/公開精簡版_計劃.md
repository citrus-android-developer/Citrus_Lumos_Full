# 公開精簡版（離職交接用）

`PRIOR-ART:` ① **最小解在既有層**——不造新機制；CLI 從既有單檔生成子集。②（r2 更正）**skill 不是「直接複製」、hooks 完全不給**：skill 須先修剪懸空引用（見 [S4-a]），Claude hooks 整組不交付（見 [S4]）。③ **世界解過**：「單一源產出 minimal 發行版」有成熟先例（busybox applet 白名單、vim tiny/huge build）。④ **裁定＝borrow-design**：借「白名單驅動的建置變體」形態，**不採**打包工具（零依賴家規，且本案是一次性產出，引入 build pipeline 不划算）。⑤（r2 更正）**自建有三支**：ast 生成腳本、機器層安裝器（[S3]）、交付文字掃描器（[S4-a-1]）——原稿寫「自建只有一支」已不成立。

## 目標（一句話）

> **新人 clone 專案 → 裝上精簡版 → 能讀懂專案既有的知識架構圖。**

不是發布一個產品，是**交接一份可讀的資產**。

★**優先序（2026-07-31 使用者更正）**★：**「可讀」是目標，「可維護」是加分**。

★**不設「機械」強制**★（2026-07-31 r1 後裁定精確化）——不擋 commit、不擋 push、不裝任何催人的 hook。交接後他們維不維護得下去，是他們的選擇，本案**不用機制去逼**。
**但紀律語氣不在此限**：被交付的 `SKILL.md` 仍保留「同一次工作內同步進架構圖」這類建議語氣——那是寫給願意維護的人看的，擋不住任何人；真正會毀掉東西的是機械閘。（此區別是 r1 審計逼出來的，原稿的「不設任何強制」在字面上涵蓋了紀律語氣，會導出「skill 要整份重寫」這個錯誤結論。）

| **Landmark 的** `CLAUDE.md` 引用 `lumos-project-notes` **9 次**（本 repo 自己的 CLAUDE.md 是 4 次，勿混），而該 skill 是 user-scope symlink 到維護者個人 clone | ★**這是真正的缺口**★——維護者離開，skill 消失，紀律區塊會叫 agent 去用一個不存在的東西 |

- 用 python 內建 `ast` 移除白名單外的**指令實作函式**、其 subparser 註冊（**含迴圈註冊形式**——`links`/`backlinks` 正是迴圈註冊）、其 dispatch 分支。

  - **正解**：刪除集 = 從「保留指令的 dispatch 分支」出發做 AST 可達性閉包後的**補集**。這個定義同時解掉「刪到還被引用的 handler」的風險（結構上不可能）。
  - ★**root 集合必須含 module-level 語句與 class body**★（r2 辯方原型實測踩到）：`scripts/lumos:7232` 有一行 module-level 的 `_SKILLS = _skills_list()`；只取 dispatch 分支當 root 會把 `_skills_list` 判進補集，產物**在 import 期就 `NameError` 全滅**。這種失敗是全滅式、當場可見，[S6] 第 2、4 道必攔，但沒必要讓它發生。

- 產物須 `compileall` 通過、SyntaxWarning 為零。
