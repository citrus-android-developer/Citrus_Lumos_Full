# 授權與著作權宣告

## 一句話

**這個 repo 一直沒有授權聲明;補上專有授權 LICENSE,把「著作權歸 CITRUS」寫明,而不是去改 1185 筆 commit 的作者欄位。**

## 背景

使用者檢視本 repo 的 commit 作者後提出:「lumos 的作者是公司行號,不應該是個人,有辦法將作者改成 CITRUS 嗎?」

排查後確認兩件事實:

1. **本 repo 完全沒有授權聲明** —— 無 `LICENSE` / `AUTHORS` / `COPYING`,README 亦無授權段。
2. **本 repo 是 public** —— 實測:在本機任何 GitHub 憑證存在之前,即可匿名 `git clone` 成功。

## 決策一:採專有授權

見 frontmatter `decisions[d1]`。

### 考慮過的方案

| 方案 | 評估 |
|---|---|
| **專有 / 保留所有權利** ✅ 採用 | 明示著作權歸公司、未授予任何授權、公開可見性不構成授權。與 repo 原狀(無授權=保留所有權利)一致。 |
| Apache-2.0 | 含專利授權與商標保留,是企業開源最常用的選擇。但本專案為公司內部工具鏈,無對外開源意圖。 |
| MIT | 最寬鬆,只要求保留著作權聲明與免責條款。同上,與意圖不符。 |

### 取捨

- **代價**:repo 仍為 public,外界看得到但不得使用。若本意是不欲外界看見,正解是把 repo 改為 private——加 LICENSE 解決不了可見性問題,這兩件事要分開處理。
- **獲得**:著作權歸屬明示、免責聲明到位(原本連免責條款都沒有,是實質風險敞口)。

## 決策二:不改寫 git 歷史

見 frontmatter `decisions[d2]`。

### 考慮過的方案

| 方案 | 評估 |
|---|---|
| **LICENSE 宣告 + 保留 author** ✅ 採用 | 不動歷史、不需 force push、保留貢獻者署名(歷史事實)。 |
| `git filter-repo` 改寫全部 author | 1185 筆 commit 的 hash 全變、需 force push 覆蓋已推送歷史、任何既有 clone 斷裂,且在未經同意下抹除 Enzo 與 Jenny Lee 的署名。 |
| 僅改 git identity,往後 commit 掛 CITRUS | 只影響未來,解決不了「歷史作者是個人」的原始訴求,且會讓個人 commit 全部匿名化。 |

### 取捨

- **代價**:`git log` / GitHub 貢獻圖上看到的仍是個人名字,不會直觀顯示公司歸屬。
- **獲得**:歷史完整可稽核、不破壞他人 clone、不涉及未經同意移除署名。
- **緩解**:LICENSE 內文與兩份 README 各含一段明文說明此區別,避免日後有人再度誤以為需要改寫歷史來表達公司歸屬。

## 未竟事項

**上游 `https://github.com/EnzoHsieh-Android/Lumos` 尚未處理。**

- 上游位於**個人帳號**下,非公司 org。
- 本帳號(`citruskenny-beep`)對其**無 push 權**——實測 `git push --dry-run` 回 `Permission denied`。
- 若僅鏡像有 LICENSE 而上游沒有,兩邊授權狀態不一致,日後鏡像同步可能覆蓋本檔。

**建議順序**:請上游持有人將 repo 透過 GitHub Transfer ownership 轉移至 `citrus-android-developer` org(保留 issue / star / fork / commit 歷史,原網址自動轉址),完成後再同步本 LICENSE。在個人帳號下掛公司 LICENSE 並非妥適做法。

## 已知限制

`lumos decision-add` 只支援 `--context` / `--why`(寫入 `context` / `why_chosen`),**不支援 ADR 四欄位中的 `alternatives_considered` 與 `trade_offs`**。而 skill 鐵則要求「decisions 一律走 `lumos decision-add`,別手改 frontmatter」。本節點的處理方式是:frontmatter 放 CLI 支援的欄位,「考慮過的方案」與「取捨」寫進本文各決策段落。若要讓 ADR 四欄位完整進 frontmatter,需先擴充 CLI。
