# r1-s4 Codex 外家席審查報告【canary:抓到——finding 11 點名〈前置實驗〉無「洪水場景」小節】

1. [blocker] A/B 無法隔離「S2 觸發放寬」本身  
   引句:「水位=N(沿用 LUMOS_IMPACT_RESCUE_N;即 free 內 direct 不足 N 席時補到 N」  
   問題：既有 `LUMOS_IMPACT_RESCUE_N` 只控制救援數量，`0` 會完全關閉 rescue；它不能在「舊零-direct 謂詞」與「新 direct<N 謂詞」間切換。若沿前案 A=0、B=N 的做法，量到的是「完全無 rescue」對「舊救援＋新放寬」，無法歸因 S2，也不是以現行 production 行為作 baseline。必須另設 predicate arm knob，或保留兩個可切換實作，使 A=現行零-direct、B=放寬，而兩臂 N 相同。  
   證據：governance/review-reports/連結缺失補全/r1-snapshot-s4.md:34；docs/lumos-toolchain-knowledge/Projects/hook必看召回修復_計劃.md:92；scripts/lumos:12034-12036

2. [major] 與前案「rescue 僅零 direct」合約候選衝突，卻沒有正式處置  
   引句:「綁定約束=保底觸發條件過保守(hook必看召回修復 刻意保守的已知代價,當時如實記錄)」  
   問題：前案原文把「rescue 僅零 direct 時觸發」列入合約候選；本案直接放寬，但未說明該候選是撤回、被哪條新候選取代、何時同步前案與對應測試。候選雖尚非已蓋章 invariant，仍是明確待治理條款，不能只稱為「已知代價」便靜默改義。  
   證據：governance/review-reports/連結缺失補全/r1-snapshot-s4.md:29；docs/lumos-toolchain-knowledge/Projects/hook必看召回修復_計劃.md:86-89；scripts/lumos:12028-12036

3. [major] 補鏈後重跑考卷，預設根本看不到新語料  
   引句:「補完重跑考卷的數字變動=真實改善的量測,如實記」  
   問題：`retrieval_eval.py` 預設把 vault 釘在 goldset 的舊 snapshot；人裁後寫入現況架構圖的引用不會出現在該快照，因此預設重跑不會產生 spec 所稱的補鏈數字變動。若改用 `--live-vault`，又失去舊 A/B 的凍結語料可比性。spec 必須定義評測模式、兩臂使用的相同語料座標，以及 history 如何標記 corpus revision。  
   證據：governance/review-reports/連結缺失補全/r1-snapshot-s4.md:47,67；governance/eval/retrieval_eval.py:296-310；governance/eval/retrieval-goldset.json:2

4. [major] 開頭仍宣稱六筆全是斷鏈，與同文勘誤及分群互相矛盾  
   引句:「held 必看 miss 6 筆全屬死法③(節點無機械可抓的 code 引用)」  
   問題：同文稍後明定 A 群三筆「已 direct 被閾砍」，只有 B 群三筆是真斷鏈。緣起段仍沿用被 pre-flight 推翻的「6 筆全屬死法③」，會使範圍、病因與 S1/S2 貢獻帳失真。  
   證據：governance/review-reports/連結缺失補全/r1-snapshot-s4.md:17,21-29,50

5. [major] 「補至水位」不只是改觸發謂詞，補入數公式尚未規格化  
   引句:「touchpoint:cmd_impact rescue 段觸發謂詞一行級」  
   問題：現碼命中後固定取 `dropped[:N]`。新語意若已有 `d` 個 surviving free direct，應只補 `N-d`；只改 `if` 會補 N 筆，最後得到 `d+N` 筆，而不是補至 N。應明定 `need=max(0,N-free_direct_count)`，再取 `dropped[:need]`，並測 N>2、存活數為 N−1、dropped 少於 need 等案例。  
   證據：governance/review-reports/連結缺失補全/r1-snapshot-s4.md:34-36；scripts/lumos:12036-12044

6. [major] 「direct ≥N」未限定 free direct，測試可能替錯謂詞背書  
   引句:「測試補「1 direct 存活+被砍 direct 存在→補至水位」「direct ≥N 不觸發」兩案」  
   問題：觸發定義數的是「free 集 direct」，但測試名稱只說 direct，沒有排除 pinned direct。現碼的 free 明確排除 pinned；若總 direct≥N 但 free direct<N，依新規仍應觸發。測試必須分開覆蓋 free direct、pinned direct、被閾砍／被 top 截斷 direct，否則可用錯誤的總數謂詞通過。  
   證據：governance/review-reports/連結缺失補全/r1-snapshot-s4.md:34,36；scripts/lumos:11988-11991,12011-12016

7. [major] D1 的核心謂詞含多個未定義概念，無法得到決定論實作  
   引句:「詞幹須 ≥6 字元且非常用詞,防 `lumos`/`eval` 這類短詞洪水」  
   問題：「詞幹」如何由含連字號、底線、CJK 或多重副檔名的檔名產生未定義；「非常用詞」沒有停用詞表或判定函式；「節點可見文字」也未說是否包含 frontmatter、summary、標題及 HTML comment。這直接違反其「同證據恆同分／決定論偵測器」目標，也使短詞不洪水測試沒有 oracle。  
   證據：governance/review-reports/連結缺失補全/r1-snapshot-s4.md:19,39,65；scripts/lumos:11468-11471

8. [major] D2 的邊集合、方向與「鏈相連」皆不完整  
   引句:「目標檔的 direct 引用節點集 D 的 wikilink 一階鄰居(related/body wikilink 雙向),且滿足任一」  
   問題：repo 的 typed edge 欄位是 `verified_by`、`plan_refs`、`related`，impact 的 via 還有 `body-wikilink`；spec 卻先把一階鄰居限定為 related/body，再以 plan_refs/verified_by 作附加條件，未定義後兩者是否也能建立鄰居、是否雙向、候選與 d 哪一端持有欄位、是否允許跨兩條邊。「鏈相連」因此無法唯一實作。  
   證據：governance/review-reports/連結缺失補全/r1-snapshot-s4.md:40；scripts/lumos:318-338,11576-11618

9. [major] 新 CLI 文法自相衝突，rc2 邊界也未定義  
   引句:「### S1 `lumos link-candidates <code-file> [--json]`(唯讀,恆 rc0;輸入壞損 rc2)」  
   問題：此處把 `<code-file>` 定為必填 positional，但稍後 `--all-goldset` 顯然應可在沒有單檔時運行；未定義兩者互斥、同給時行為、goldset 路徑是否可指定。此外「輸入壞損」沒有列出不存在、目錄、repo 外路徑、非 tracked 檔、goldset JSON/schema 壞損各自 rc。現有 argparse 命令通常明確建互斥檢查並回 rc2，本 spec 尚不足以加入子命令表。  
   證據：governance/review-reports/連結缺失補全/r1-snapshot-s4.md:38,43；scripts/lumos:12795-12808,12955-12971

10. [major] JSON 輸出 schema 不封閉，`both` 尤其無法表示  
    引句:「輸出:逐候選 `{node, signal, via/evidence}`;無候選印「無」。」  
    問題：`via/evidence` 是替代欄、條件欄還是字面欄名未定義；`signal=both` 時是否同時必有 via 與 evidence、其型別是字串、物件或陣列也未定義。`--json` 的頂層形狀、空結果、證據行號／摘錄欄位及 `--all-goldset` 彙總 schema 都缺失，測試無法建立穩定合約。  
    證據：governance/review-reports/連結缺失補全/r1-snapshot-s4.md:41-43,65
